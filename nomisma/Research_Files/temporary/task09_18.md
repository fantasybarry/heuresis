# Task 09_18 — Proposed validation and parameter-calibration plan

Date: September 18, 2026

Status: **Proposed — not yet executed.** This document combines the preceding
next-step plan and parameter proposal. Existing planner settings and the frozen
baseline remain unchanged.

## Starting evidence

The completed development sweep tested 27 configurations and four stress
scenarios across nine sessions. All 454 tests passed.

The baseline generated 71 alerts and 37 orders. Four orders filled and 33 expired.
All simulated trades occurred in FTFT on September 14. The observed leader earned
$15.45 from three trades on that same day. This evidence is insufficient to
establish reliable calibrated parameters; the selected configuration remains null.

## Proposed next plan

### 1. Explain the missing executions

- [ ] Produce a breakdown for every symbol and session:
  data coverage → eligibility → alerts → plans → orders → fills.
- [ ] Identify why the 33 baseline orders expired.
- [ ] Quantify how missing bars affected eligibility.
- [ ] Distinguish data limitations, strategy filters and fill assumptions from
  genuine absence of qualifying opportunities.

**Deliverable:** An eligibility and fill audit identifying the main constraints.
The audit should explain the sparse execution evidence before further calibration.

### 2. Freeze the next experiment's rules

- [ ] Specify capital, risk limits, acceptable drawdown, execution assumptions
  and required estimation precision.
- [ ] Register the historical universe, development dates, validation periods,
  acquisition budget and acceptance criteria before inspecting new outcomes.
- [ ] Preserve the current baseline and the existing 27-configuration grid.

**Deliverable:** A registered expansion and validation protocol.

### 3. Expand data in stages

- [ ] Check historical stock membership and minute coverage first.
- [ ] Select stocks using information available at the time of selection.
- [ ] Acquire quotes and trades within the registered budget.
- [ ] Retain rejected opportunities and incomplete sessions in the evidence.

**Deliverable:** A documented dataset covering broader trading periods and
opportunities, with explicit coverage limitations.

### 4. Measure intraday portfolio risk

- [ ] Add portfolio equity and drawdown calculations covering cash, open
  positions and exit costs.
- [ ] Represent stale or missing quotes explicitly.
- [ ] Verify that the resulting risk measurements capture losses occurring
  within the session.

**Deliverable:** Intraday portfolio risk measurements. Session-closing cash alone
is insufficient because it can hide losses that occurred earlier in the day.

### 5. Repeat chronological validation

- [ ] Compare the same 27 configurations across broader trading periods.
- [ ] Examine consistency across dates and neighboring parameter values.
- [ ] Repeat cost and delay sensitivity tests.
- [ ] Estimate uncertainty while accounting for every tested parameter variation.

**Deliverable:** A comparison against the registered acceptance criteria,
including an explicit insufficient-evidence outcome when appropriate.

Searching multiple configurations increases overfitting risk; the validation
must account for that search. [Research basis: The Probability of Backtest
Overfitting](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf).

### 6. Evaluate one frozen candidate on an untouched holdout

- [ ] Freeze one candidate only after the development selection criteria are met.
- [ ] Open the later holdout dataset only after that decision is frozen.
- [ ] Evaluate the candidate once against the registered requirements.
- [ ] Leave the selected configuration empty if validation fails or remains
  insufficient.

**Deliverable:** A documented acceptance, rejection or insufficient-evidence
decision for the frozen candidate.

## Parameter proposal

The candidate for further validation is a **1 ATR stop, 2.5 reward multiple and
30-minute maximum hold**. It is the observed development leader, not an approved
replacement for the baseline.

| Parameter | Frozen baseline | Observed leader | Existing test range |
| --- | ---: | ---: | --- |
| Stop ATR multiplier | 1.5 | 1.0 | 1, 1.5, 2 |
| Reward multiple | 2 | 2.5 | 2, 2.5, 3 |
| Maximum holding time | 15 minutes | 30 minutes | 5, 15, 30 |

### Validate the existing exit-parameter grid

- [ ] Keep the baseline unchanged while evaluating the grid on broader evidence.
- [ ] Seek consistent results across dates and nearby settings, rather than
  selecting solely by the highest observed profit.

### Investigate entry parameters after the execution audit

| Entry parameter | Frozen value |
| --- | ---: |
| Breakout lookback | 5 bars |
| Chase allowance | 0.25 ATR |
| Order validity | 120 seconds |

- [ ] Determine whether these parameters explain the expired orders.
- [ ] Treat expiry as a diagnostic observation; it does not by itself establish
  that a parameter is wrong.
- [ ] Register a small new entry-parameter experiment only after identifying
  the cause. No new entry ranges are selected in this proposal.
- [ ] Revalidate exit parameters after any entry-rule change, because entry
  rules change which trades reach the portfolio.

### Separate constraints and measured assumptions from strategy parameters

- [ ] Obtain capital and loss limits from the user's requirements.
- [ ] Measure or justify fees, latency and fill-capacity assumptions.
- [ ] Keep those constraints and assumptions from being adjusted merely to
  improve backtest profits.
