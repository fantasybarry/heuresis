# Intraday monitoring implementation contract

Python 3.9+ standard library; no runtime package installs. Preserve daily screener. Focus on intraday penny-stock momentum, with an independent monitor configuration and streaming Alpaca prices. No trading/order endpoints. Label Buy / Strong buy as technical setup alerts, never calibrated forecasts. All timestamps ISO8601 with timezone.

## Ownership

- Provider agent: `nomisma/live_data.py`, `tests/test_live_data.py` only.
- Metrics agent: `nomisma/monitor_metrics.py`, `tests/test_monitor_metrics.py` only.
- Frontend agent: `nomisma/static/*` only (add live.js/live.css; modest integration into existing app.js/index.html).
- Root: `nomisma/monitor.py`, server.py/storage.py/run.py/env/docs, service tests and browser checks.

## Config (metrics module validates; defaults exported)

`DEFAULT_MONITOR_CONFIG = {source:'demo',symbols:['DEMO','MOMO','GAP'],min_price:0.5,max_price:5,min_session_volume:100000,min_relative_volume:1.5,max_spread_pct:2,buy_score:65,strong_buy_score:85,confirmation_bars:2,cooldown_seconds:300,alerts_enabled:true}`.

`validate_monitor_config(payload,current=None)->full config`; reject unknown keys, types/nonfinite/bounds, at most20 unique canonical ticker symbols. Source demo/alpaca only. Floats separate from config. min_relative_volume is **latest completed 1-minute bar / preceding20 completed 1-minute bars**, NOT time-adjusted daily volume. Alert gate uses min_session_volume, price range, spread threshold; never silently treat missing quotes/volume/baselines as passing. min_session_volume zero allowed. confirmation_bars1..5 cooldown30..3600, buy< strong both0..100, maxspread0.01..20, min_price>0 max<=1m.

## Normalized provider bundle

`{source:'alpaca'|'demo',feed:'iex'|'sip'|'synthetic',as_of:timestamp,warnings:[],session:{date:'YYYY-MM-DD',open:timestamp,close:timestamp,previous_date:'YYYY-MM-DD'},assets:[{symbol,name,sector,exchange,bars:[{date,open,high,low,close,volume}],minutes:[{t,open,high,low,close,volume,vwap}],snapshot:AlpacaSnapshot,float:{shares,as_of:'YYYY-MM-DD',source:'FMP'|'Manual'|'Synthetic'}|null}]}`.

`bars` contains at least30 prior completed sessions (exclude bundle.session.date and future dates); these use split-adjusted OHLCV. `minutes` contains **all available regular-session completed1min bars for bundle.session.date** (not a tail only, for correct session VWAP/volume; <=390). Snapshot raw Alpaca `{latestTrade:{t,p,s,...},latestQuote:{t,bp,ap,...},minuteBar:{t,o,h,l,c,v,vw},dailyBar:{t,o,h,l,c,v,vw},prevDailyBar:{...}}`. Daily bars may cover extended hours; do NOT use their open as regular-session opening price. Exchange/calendar explicit; if today isn't trading day choose most recent session, so engine suppresses closed-market alerts.

## Provider module public API

- `live_provider_status()->{alpaca_configured,feed,float_configured}` credentials remain server-side.
- `load_live_seed(symbols,progress=None,stop_event=None)->bundle`: fixed-host GET-only Alpaca calendar, snapshots, split-adjusted prior daily bars ~90calendar days, today's regular-session completed minute history with full pagination. Account hosts honor ALPACA_PAPER. No fallback demo. Optional float via FMP_API_KEY and stable `/stable/shares-float?symbol=X`; float failures warnings, do not fail prices. Key/name/secret never logged/exposed. Latest SIP requires entitled real-time feed; no delayed feed substituted.
- `fetch_float(symbol)->{shares,as_of,source:'FMP'}|null`: only actual floatShares, NOT outstandingShares, float percentages, marketcap or estimates. FMP fixed HTTPS host financialmodelingprep.com with redirect denial, timeouts, bounded errors; don't print secret query string on error. Source date from provider; unavailable date means null/unusable. root caches and allows manual entries.
- `stream_live(symbols,on_event,stop_event,on_status=None)`: one websocket session, auth+subscribe verified, trades/quotes/bars/updatedBars/dailyBars. Callback status strings `connecting`, `live`; event callback gets raw Alpaca event dict with `T`. Client fixed TLS `wss://stream.data.alpaca.markets/v2/{iex|sip}` certificate verification, handshake Accept validation, masked outbound frames, bounded frames, partial/fragmented reads, ping/pong, close, cancellable timeouts. No reconnect internally: return on stop, raise sanitized ValueError on error/close; root reseeds and retries with backoff. On status live only after successful auth + subscription ack. Use stdlib implementation (tests meaningful transport/protocol cases). Late updates forwarded; never sum trade sizes into daily volume (condition/correction pitfalls).

## Metrics module public API

- `build_rows(bundle,config,now=None)->list[rows]`: now aware datetime, default UTC now. Pure deterministic no I/O. Engine handles events already merged by root into normalized bundle minutes/snapshot. Use current session date, all regular-minute history; no previous day's minutes. Skip unfinished minutes and malformed/duplicate/out-of-order input safely, no forward data. Finite/null outputs.
- `demo_bundle(symbols,step=0)->bundle`: deterministic synthetic penny-stock bundle, at least30daily histories and>=40 completed1min bars. Synthetic session and clock explicitly historical, advancing1minute per step for simulation. All rows source demo. Demo should demonstrate Watch -> Buy -> Strong buy as step advances with plausible data; timestamps share fixed simulation date, source labels unambiguous. Root calls every3s with step increment and passes datetime.fromisoformat(bundle.as_of) to build_rows.
- Row: `{symbol,name,source,feed,price,price_at,quote_at,volume_at,session_date,session_volume,volume_30d_total,avg_volume_30d,relative_volume,minute_relative_volume,float_shares,float_as_of,float_source,float_turnover,gap_pct,change_pct,spread_pct,vwap,ema9,ema20,rsi,signal_score,signal:'Watch'|'Buy'|'Strong buy',alert_eligible:bool,signal_bar_at:timestamp|null,reasons:[str],blockers:[str],warnings:[str],stale:bool,market_open:bool,chart:[{t,close,volume}],volume_history:[{date,volume}],signals:[{name,points,max_points,description}]}`.

Definitions: volume30 totals and mean use **30 prior trading sessions excluding current day**, label that in UI; missing30 => bothnull and noalert. `session_volume` sum valid regular1minute volumes through last completedminute; `volume_at` is lastminute end timestamp. Not raw trade sums. `relative_volume` =session_volume/full-session avg30 (explicit not time-of-day-adjusted). `minute_relative_volume` lastcompletedminutevolume / preceding20regular-minutevolume average. VWAP=sum(minutebar.vwap*volume)/sumvolume across regular session; do not approximate typicalprice when vwap missing, set null/blockalerts. Gap=first regular09:30 (orcalendaropen) minute.open vs split-adjusted prior-date close; no exact openingbar=>gapnull. `change_pct` latestprice vs samepriorclose; float_turnover=session_volume/float if available, source date shown; future/invalidfloat=>null. Trade price may be current display but technical scoring price is completedminute close. Recent price<=30sec, quote<=30sec, lastcompletedminuteend<=120sec, currentmarketregular session, full30day history, contiguous recent21minutes required for eligiblealerts; stale/missingdata suppressalerts. Extended-hours display can show quotes but noalerts until regularsession conditions valid. Ratio of raw snapshot.prevDailyBar.close vs adjusted previous close suggests corporate action: warn if >20% diff; gap uses adjusted reference. Halt stream not guaranteed; surface caution, not claim allhalts detected.

Suggested score100: close>sessionVWAP20; EMA9>EMA20 20; EMA9 rising10; RSI50..7515; minuteRVOL>=configmin15; close>prior5minutehigh10; positive daychange10. Buy>=configbuy, Strong>=strong; both require VWAP+EMA trend, RVOL and quote/liquidity/freshness guards. An ineligible row remains Watch with blockers. Confirmation/cooldown root handles. Explain heuristic not accuracyclaim.

## Monitor service and browser API (root)

Status `{running,connection:'stopped'|'loading'|'connecting'|'live'|'reconnecting'|'error'|'demo',message,error,source,feed,updated_at,session,warnings}`. rows above. alerts latest100 persisted, each `{id,symbol,level:'Buy'|'Strong buy',source,feed,created_at,market_time,price,score,reasons,acknowledged}`. Browser view should show Buy setup / Strong buy setup.

GET `/api/monitor/events`: SSE `event: monitor\ndata: <same snapshot as GET>\n\n` at most1/sec and heartbeat every15s; app can fallback GET every2s on SSEerror. Price events via upstream real websocket, browser updates throttled1s. No streams/alerts start automatically on initial visit/restart; userStart explicit.

POST `/api/monitor/config`: partial config -> `{config}`; reject while running with409 (stop thenedit). POST `/api/monitor/start`: optional full/partial config, persists, returns monitor snapshot202 immediately. Validate creds before launching.
