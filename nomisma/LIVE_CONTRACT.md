# Intraday monitoring implementation contract

Python 3.9+ standard library; no runtime package installs. Preserve daily screener. Focus on intraday penny-stock momentum, with an independent monitor configuration and streaming Alpaca prices. No trading/order endpoints. Label Buy / Strong buy as technical setup alerts, never calibrated forecasts. All timestamps ISO8601 with timezone.

## Ownership

- Provider agent: `nomisma/live_data.py`, `tests/test_live_data.py` only.
- Metrics agent: `nomisma/monitor_metrics.py`, `tests/test_monitor_metrics.py` only.
- Frontend agent: `nomisma/static/*` only (add live.js/live.css; modest integration into existing app.js/index.html).
- Root: `nomisma/monitor.py`, server.py/storage.py/run.py/env/docs, service tests and browser checks.

## Config (metrics module validates; defaults exported)

`DEFAULT_MONITOR_CONFIG = {source:'demo',symbols:['DEMO','MOMO','GAP'],min_price:0.5,max_price:5,min_session_volume:100000,buy_score:65,strong_buy_score:85,confirmation_bars:2,cooldown_seconds:300,alerts_enabled:true}`.

`validate_monitor_config(payload,current=None)->full config`; reject unknown keys, types/nonfinite/bounds, at most 50 unique canonical ticker symbols. Source demo/alpaca only. Floats separate from config. Retired keys `min_relative_volume` and `max_spread_pct` are dropped on load; minute RVOL and spread are displayed but no longer gate alerts. `min_session_volume` sets the minimum **regular-session volume** (premarket excluded), summed from the completed regular-session minute bars present (a lower bound); rows expose `volume_filter_basis:'regular_session'`. Zero is allowed. Price, history, and regular-session technical guards still apply; never silently treat missing inputs as passing. confirmation_bars1..5 cooldown30..3600, buy< strong both0..100, min_price>0 max<=1m.

The application cap is separate from provider entitlement. Alpaca Basic permits 30 streamed symbols; larger lists require an eligible plan. A provider symbol-limit rejection is terminal and actionable, with the configured list preserved for editing. No silent symbol truncation or feed substitution. [Alpaca market-data plans](https://docs.alpaca.markets/us/docs/about-market-data-api)

## Normalized provider bundle

`{source:'alpaca'|'demo',feed:'iex'|'sip'|'synthetic',as_of:timestamp,warnings:[],session:{date:'YYYY-MM-DD',open:timestamp,close:timestamp,previous_date:'YYYY-MM-DD'},assets:[{symbol,name,sector,exchange,bars:[{date,open,high,low,close,volume}],minutes:[{t,open,high,low,close,volume,vwap}],snapshot:AlpacaSnapshot,float:{shares,as_of:'YYYY-MM-DD',source:'FMP'|'Manual'|'Synthetic'}|null}]}`.

`bars` contains at least30 prior completed sessions (exclude bundle.session.date and future dates); these use split-adjusted OHLCV. `minutes` contains **all available regular-session completed1min bars for bundle.session.date** (not a tail only, for correct session VWAP/volume; <=390). Snapshot raw Alpaca `{latestTrade:{t,p,s,...},latestQuote:{t,bp,ap,...},minuteBar:{t,o,h,l,c,v,vw},dailyBar:{t,o,h,l,c,v,vw},prevDailyBar:{...}}`. Daily bars may cover extended hours; do NOT use their open as regular-session opening price. Exchange/calendar explicit; if today isn't trading day choose most recent session, so engine suppresses closed-market alerts.

## Provider module public API

- `live_provider_status()->{alpaca_configured,feed,float_configured}` credentials remain server-side.
- `load_live_seed(symbols,progress=None,stop_event=None,refresh=False)->bundle`: fixed-host GET-only Alpaca calendar, snapshots, split-adjusted prior daily bars ~90calendar days, today's regular-session completed minute history with full pagination. Account hosts honor ALPACA_PAPER. No fallback demo. Optional float via FMP_API_KEY and stable `/stable/shares-float?symbol=X`; float failures warnings, do not fail prices. Key/name/secret never logged/exposed. Latest SIP requires entitled real-time feed; no delayed feed substituted.
- `fetch_float(symbol,refresh=False)->{shares,as_of,source:'FMP'}|null`: only actual floatShares, NOT outstandingShares, float percentages, marketcap or estimates. FMP fixed HTTPS host financialmodelingprep.com with redirect denial, timeouts, bounded errors; don't print secret query string on error. Source date from provider; unavailable date means null/unusable. root caches and allows manual entries.
- `stream_live(symbols,on_event,stop_event,on_status=None)`: one websocket session, auth+subscribe verified, trades/quotes/bars/updatedBars/dailyBars. Callback status strings `connecting`, `live`; event callback gets raw Alpaca event dict with `T`. Client fixed TLS `wss://stream.data.alpaca.markets/v2/{iex|sip}` certificate verification, handshake Accept validation, masked outbound frames, bounded frames, partial/fragmented reads, ping/pong, close, cancellable timeouts. No reconnect internally: return on stop, raise sanitized ValueError on error/close; root reseeds and retries with backoff. On status live only after successful auth + subscription ack. Use stdlib implementation (tests meaningful transport/protocol cases). Late updates forwarded; never sum trade sizes into daily volume (condition/correction pitfalls).

## Metrics module public API

- `build_rows(bundle,config,now=None)->list[rows]`: now aware datetime, default UTC now. Pure deterministic no I/O. Engine handles events already merged by root into normalized bundle minutes/snapshot. Use current session date, all regular-minute history; no previous day's minutes. Skip unfinished minutes and malformed/duplicate/out-of-order input safely, no forward data. Finite/null outputs.
- `demo_bundle(symbols,step=0)->bundle`: deterministic synthetic penny-stock bundle, at least30daily histories and>=40 completed1min bars. Synthetic session and clock explicitly historical, advancing1minute per step for simulation. All rows source demo. Demo should demonstrate Watch -> Buy -> Strong buy as step advances with plausible data; timestamps share fixed simulation date, source labels unambiguous. Root calls every3s with step increment and passes datetime.fromisoformat(bundle.as_of) to build_rows.
- Row: `{symbol,name,source,feed,price,price_at,quote_at,volume_at,session_date,session_volume,volume_30d_total,avg_volume_30d,relative_volume,minute_relative_volume,float_shares,float_as_of,float_source,float_turnover,gap_pct,change_pct,spread_pct,vwap,ema9,ema20,rsi,signal_score,signal:'Watch'|'Buy'|'Strong buy',alert_eligible:bool,signal_bar_at:timestamp|null,reasons:[str],blockers:[str],warnings:[str],stale:bool,market_open:bool,chart:[{t,close,volume}],volume_history:[{date,volume}],signals:[{name,points,max_points,description}]}`.

Extended-hours display can show quotes but noalerts until regularsession conditions valid. ## Monitor service and browser API (root)

GET `/api/monitor`: `{config,status,rows,alerts,provider_status,limits:{max_symbols:50}}`. Status `{running,connection:'stopped'|'loading'|'connecting'|'live'|'reconnecting'|'error'|'demo',message,error,source,feed,updated_at,session,warnings,refresh}`. `refresh` is `{state:'idle'|'loading'|'completed'|'error'|'cancelled',started_at,completed_at,error}`. rows above. `alerts` contains the latest100 persisted alerts matching the captured `config.source`, each `{id,symbol,level:'Buy'|'Strong buy',source,feed,created_at,market_time,price,score,reasons,acknowledged}`. Apply source filtering before the limit, including while monitoring is stopped. The main Setup alerts panel and unread count show only this configured source. Browser view should show Buy setup / Strong buy setup.

GET `/api/monitor/events`: SSE `event: monitor\ndata: <same snapshot as GET>\n\n` at most1/sec and heartbeat every15s; app can fallback GET every2s on SSEerror. Price events via upstream real websocket, browser updates throttled1s. No streams/alerts start automatically on initial visit/restart; userStart explicit.

Both snapshot endpoints accept `?compact=1` to omit only `chart` and `volume_history` from rows; full snapshots remain the default for existing clients. The radar uses compact snapshots. GET `/api/monitor/symbol/<ticker>` returns `{row}` with full chart/history for an open stock report, 404 if no current row is available, or 400 for an invalid symbol. CSV exports and saved alert evidence retain their existing fields.

POST `/api/monitor/config`: partial config -> `{config}`; reject while running with409 (stop thenedit). POST `/api/monitor/start`: optional full/partial config, persists, returns monitor snapshot202 immediately. Validate creds before launching. POST `/api/monitor/stop`: {} returns snapshot; prompt stop event and no lateralerts fromoldgeneration. Switching config requiresstop; reconnect preserves the same configured set of up to 50 symbols.

POST `/api/monitor/refresh`: `{}` -> monitor snapshot, HTTP 202. Reload the active provider's quotes, prior daily bars, current minute history, and optional float data asynchronously without restarting the stream or clearing confirmation/cooldown state. Newer streaming trades, quotes, minute revisions, and daily aggregates take precedence over an older request. Manual float overrides take precedence; explicit refresh bypasses provider float cache. Demo refresh recomputes the current simulated minute without rewinding the session. Stopped, connecting, reconnecting, or already-refreshing monitors return 409. Stop/restart invalidates pending work, and refresh failures preserve existing data with a sanitized error. The UI exposes progress through `status.refresh` and does not use refresh to change symbols, reload credentials, or rerun other research jobs.

POST `/api/monitor/float`: `{symbol,shares,as_of}` -> `{float}`; validated positivewhole shares<=1e13, date<=today. `{symbol,shares:null}` clears manualoverride. Datedmanualvalue persists and overridesFMP; never advertise as providerverified. Same-source floats cached acrossstarts at most24h. UI can save for unavailablefloat. Demo alwayssynthetic, manualrealoverrides don't applydemo.

POST `/api/monitor/alerts/ack`: `{id}` or `{all:true}`, with optional `source:'demo'|'alpaca'`, -> `{alerts}`. An explicit source scopes both acknowledgment and returned summaries; a mismatched id remains unchanged. The main Setup alerts panel sends its configured source for acknowledgment, including Mark all read. Omitting source preserves the all-source API behavior. Acknowledgment persists and never deletes evidence. The research journal GET `/api/monitor/alerts` remains paginated across all sources, so earlier synthetic and Alpaca records remain accessible when the monitor source changes. GET `/api/monitor/export.csv`: monitor rows allrequestedfields inclprovenance, formula-safe. ## Research extensions (September 2026)

Rows additionally freeze `decision_at` and `planning_quote` for the built-in research planner. The quote preserves bid/ask, raw and normalized share sizes, source/feed, event time, original receipt time and unit basis. Streaming receipt is stamped at accepted arrival, REST receipt at response receipt; render/refresh never invent a receipt for an old quote. SIP quotes on/after 2025-11-03 use documented share units directly; unverified legacy/IEX conversion stays unavailable. Synthetic sizes/receipts use the simulated clock explicitly.

New alerts freeze model output and assumptions independently of observed outcomes. Missing legacy model evidence cannot be reconstructed. A separate current-analysis action uses a fresh monitored row without altering the original. The model uses stricter five-second quote freshness and minute ATR, not daily ATR. Account context needs complete explicit confirmation within five minutes. All parameters, costs, price grids and capacity rules remain research assumptions. See [TRADE_PLANNER.md](TRADE_PLANNER.md) and the planner endpoints in [API_CONTRACT.md](API_CONTRACT.md).

Rows add `day_volume_fresh`, `day_volume_basis`, `day_volume_partial`, `volume_filter_basis`, `avg_volume_3m`, `avg_daily_volume`, `day_relative_volume`, `spread` (dollars), `spread_fresh`, `beta`, `beta_observations`, `atr`, `atr_pct`, `history_as_of`, `history_expected_as_of`, `history_sessions`, and `metric_availability`. The averages use 63 and 20 prior sessions; day RVOL is fresh total day volume / 20-session average, without time-of-day adjustment. Fresh spread requires positive bid/ask with ask at least bid and a quote no more than 30 seconds old. Beta uses at most 252 simple split-adjusted daily price returns versus SPY with identical return start/end dates, requiring 60 observations and positive benchmark variance. ATR uses Wilder 14-period true-range smoothing; ATR percentage divides by the last prior adjusted close. Intraday technical session/minute RVOL definitions remain separate.

`screening_metrics.history_metrics` supplies prior-session metrics, and `rank_rows` adds `liquidity_volatility_score`, `rank`, `ranking_components`, `ranking_available_metrics`, `ranking_missing_metrics`, and `ranking_metric_coverage_pct`. Component entries are `{value,weight,available,percentile,points}`. Percentile ranking weights are total day volume 15, 63-session average volume 10, 20-session average volume 10, day RVOL 20, inverse spread percentage 15, positive beta 10, and ATR percentage 20. Missing metrics earn zero without redistributing their weights; measured zero/negative beta earns zero beta points. Ties use average percentile rank, with a sole available value receiving full component points. Overall score ties use ticker order. This ranks the monitored set independently of candidate-pool ranking and does not create Buy/Strong buy signals or alter their confirmation rules. See METHODOLOGY.md for calculation limits.

Total day volume uses a current New York dated provider daily aggregate, which includes eligible extended-hours trade volume. If absent, available completed minute volume from 04:00 through 20:00 New York can be shown with an explicit partial fallback basis; do not add it to the daily aggregate or reset the total at the regular open. A provider daily aggregate replaces that fallback when available. Missing or stale volume remains identified independently of quote and minute freshness. Stale day volume and spread earn no ranking points even if an old displayed value is retained.

For the live monitor, fallback freshness requires both receipt and the latest included completed-minute end to be no more than 120 seconds old. Discovery uses the same 120-second fallback check before filtering and again after historical enrichment; its provider daily aggregates retain a 300-second receipt limit. In discovery rows, `volume_at` is the fallback's actual completed-minute end, while `volume_received_at` is receipt time. These discovery fields do not change the monitor's `volume_at`, which identifies its regular-session technical minute end. A positive discovery minimum-volume filter excludes stale fallbacks. With a zero minimum, the row and partial total remain visible, `day_volume_fresh` is false, day RVOL is null, and those inputs earn no ranking points. `coverage.expired_volume_during_enrichment` reports rows excluded when a fallback ages out during history loading.

Shared table cells show **Stale volume** when a finite retained total has `day_volume_fresh:false`; otherwise a true `volume_partial` or `day_volume_partial` shows **Partial volume**. Stale takes precedence over partial. Discovery fallback tooltips show the actual completed-minute time and explain that stale volume/day RVOL earn no points. After history loading, discovery makes bounded same-feed latest-quote requests for stale, missing, or invalid selected-pool quotes. Actual provider timestamps still must satisfy the 30-second limit, checked again before ranking; failures remain unavailable. This is separate from the monitor's ongoing quote stream and does not refresh candidate trade or volume timestamps. See API_CONTRACT.md for batching and coverage fields.

Candidate discovery has its own persisted configuration and disabled-by-default weekday schedule at `09:15 America/New_York`. It retains the last successful result, catches up for the current weekday after opening, and does not change or start the monitor. The daily screener schedule remains independent. The provider loader runs independent requests concurrently with bounded workers; radar snapshots omit chart/history through the compact API and reports request full rows as needed. See API_CONTRACT.md for discovery settings, status, retries, and endpoint envelopes.

Rows now include `eligibility` with the primary blocker and numeric threshold checks, `confirmation` with completed/required bar counts and cooldown information, current-session `trading_status` and `price_bands`, plus OHLC/volume/VWAP/EMA9/EMA20 fields in each chart point. Required price subscriptions still determine Live status. Optional `statuses`/`lulds` subscriptions are attempted individually after the required ACK and reported through an internal `nomisma_subscription` callback. Entitlement rejection for an optional channel does not substitute another feed or drop an otherwise valid price subscription. Confirmed halts block alerts; an absent status event stays unknown.

Alert evidence schema v1 adds frozen `config`, `snapshot`, `session`, `session_date`, `reference_price`, `reference_at`, `observation_basis`, and `outcomes` keyed by 5/15/30 minutes. Outcomes have pending/observed/unavailable status, reason, target timestamp, close change, adverse excursion, and end close. Full details are returned by `/api/monitor/alerts/<id>`; summaries omit the large frozen objects. A local metadata index supports reconciliation for only the current source/feed/session. Older alerts remain readable and cannot gain invented original evidence.

See API_CONTRACT.md for asynchronous diagnostics/discovery, paginated histories, and local backup/restore routes; README.md and METHODOLOGY.md describe the user workflow and exact observation definitions.
