# Nomisma implementation contract

Local Python 3.9+ standard-library app. No runtime packages required. UI is vanilla HTML/CSS/JS served from `nomisma/static/`. All paths below are relative to `nomisma/` in the Heuresis repository. This file documents the internal API, not investment methodology.

## Engine (`nomisma/engine.py`)

The separate research planner is documented below and in [TRADE_PLANNER.md](TRADE_PLANNER.md).

Expose `DEFAULT_FILTERS`, `PRESETS` (list of `{id,name,description,filters}`), `validate_filters(dict) -> dict` (raise ValueError with useful field error), and `screen(dataset, filters) -> dict`.

Filters: min_price=10, max_price=1000, min_avg_volume=500000, min_relative_volume=1.0, min_rsi=45, max_rsi=75, min_score=55, above_sma50=true, above_sma200=false, positive_macd=false, min_return_20d=0, max_atr_pct=10, sectors=[] (empty means all). All numeric fields finite, sensible bounds and min/max consistency, reject unknown keys. Engine computes RSI14 (Wilder), SMA20/50/200, EMA12/26 and MACD9 signal, ATR14, 20-day return, prior-20-day average volume, relative volume, distance to prior-20-day high and 20-day excess return vs SPY. Require 201 valid unique ordered daily bars. Score 0..100, transparent weighted components; never label score probability. No forward-looking data. Exclude stale symbols compared with latest benchmark or dataset bar date and flag stale overall data (>5 calendar days).

Dataset: `{source:'demo'|'alpaca'|'csv',label,feed,as_of:'YYYY-MM-DD',warnings:[],assets:[{symbol,name,sector,exchange,bars:[{date,open,high,low,close,volume}]}],benchmark:{symbol:'SPY',bars:[...]}}`. Benchmark may be null. Only completed daily sessions from provider; demo must be clearly synthetic with fixed historical date.

Screen returns `{as_of,source,label,feed,warnings,universe_count,eligible_count,matched_count,rejected:{reason:count},results:[{symbol,name,sector,exchange,price,change_pct,score,setup,as_of,metrics:{rsi,relative_volume,avg_volume,sma20,sma50,sma200,macd,macd_signal,macd_histogram,atr,atr_pct,return_20d,relative_strength,breakout_distance},signals:[{name,points,max_points,description}],risks:[str],chart:[{date,close,volume}]}],market:{symbol:'SPY',price,change_pct,return_20d,above_sma50,chart:[{date,close}]}|null,filters}`. Sorted descending score, tie symbol. Engine validation and financial edge-case tests in `tests/test_engine.py`.

## Data (`nomisma/providers.py`)

Expose `provider_status() -> {alpaca_configured:bool,feed:str}`, `demo_dataset() -> dataset`, `parse_csv(text) -> dataset` (validate, max 20MB, headers symbol,date,open,high,low,close,volume; optional name,sector,exchange; SPY benchmark), `fetch_alpaca(universe='curated', symbols=None, progress=None) -> dataset`. `progress(message)` callback optional. `curated` ~50 liquid ticker starter universe, `all` all active tradable NASDAQ/NYSE/AMEX/ARCA equities from assets API, `custom` list of validated tickers. Environment keys `ALPACA_API_KEY`, `ALPACA_SECRET_KEY`, `ALPACA_FEED` default iex. Credentials stay server-side. GET requests only to fixed Alpaca hosts, timeouts, bounded retries, batching, pagination, split-adjusted daily bars ~450 calendar days history, strict errors without silent demo fallback. Query API calendar for most recent completed session including early closes, 30-minute buffer, no incomplete daily bars. Clearly warn that IEX volume is exchange-specific and all-equities universe may include ETFs. Live network tests optional/mocked tests mandatory. Own provider tests and sample CSV.

## Server API (root implements)

Run with `python3 run.py` (default localhost:8765). Optional `--port`, `--scan`, `--data-dir`. SQLite state under ignored `data/`. Server loads project `.env` if present without overriding existing environment.

GET `/api/bootstrap`: `{settings:{filters,source,universe,symbols,schedule:{enabled,time,timezone}},presets:[{id,name,description,filters}],watchlist:[symbol],latest:scan|null,history:[{id,created_at,source,as_of,matched_count}],job:{running,message,error,scan_id},provider_status:{alpaca_configured,feed,csv_available}}`.

Scan is screen result plus `{id,created_at}`. Initial bootstrap creates and persists demo scan, source explicitly demo. GET `/api/status`: `{job,latest,history}`. An optional `?since=<latest-id>` returns `latest:null` when the latest result is unchanged, reducing polling payloads. GET `/api/scans/<id>`: scan. Custom universes accept at most 1,000 symbols.

POST `/api/scan`: `{filters,source:'demo'|'alpaca'|'csv',universe:'curated'|'all'|'custom',symbols:[...]}` returns `{job}` immediately (202); UI polls `/api/status`. Only one scan runs at once; 409 otherwise. Backend validates before launching. Failed live scan never falls back to demo.

POST `/api/settings`: settings object above, returns `{settings}`. Preserve unspecified top-level fields. Schedule timezone is America/New_York only for now. Time validated HH:MM. Schedule runs once per local weekday once due, with startup catch-up, persists last success date; failed schedules retry with backoff. Requires process running. Schedule source and filters follow saved settings.

POST `/api/watchlist`: `{symbol,enabled:bool}` returns `{watchlist:[...]}`.

POST `/api/presets`: `{name,filters}` returns `{presets:[...]}`; custom preset id persisted. Built-in presets read-only.

POST `/api/import`: `{csv:string}` validates and stores CSV dataset; returns `{asset_count,as_of}`. Follow with scan source csv; settings source may be saved separately.

GET `/api/export.csv?scan=<id>` returns current matching results, CSV escaped and formula-safe.

Errors JSON `{error:string}`. Unknown endpoints 404. UI should show error, loading and empty states. No data/keys via static handler. Mutations accept application/json except the binary restore route, and reject foreign Origin; server bound to loopback.

## Research and workspace extensions

### Built-in planner API

- GET `/api/planner/settings` returns `{settings:{policy,context,costs}}`.
- POST `/api/planner/settings` accepts partial policy/cost changes or null account/cost resets. Updating context requires `confirm_context:true` and every equity/cash/risk/notional/positions field. The server stamps `as_of`; policy/cost updates never renew it. Invalid types, unknown keys and nonfinite values are rejected. The complete positions map replaces the previous map.
- GET `/api/planner/alerts/<id>` returns `{alert_id,symbol,source,feed,plan,viewed_at,message}`. `plan` is the original frozen analysis, or null for legacy alerts. It does not reconcile outcomes or change storage.
- POST `/api/planner/analyze` accepts only `{alert_id}`. A running matching source/feed and monitored symbol are required. It evaluates the current row with current settings and returns the same envelope with `kind:current_reanalysis`. It never rewrites the original alert or starts a monitor. Invalid/stopped/mismatched requests return 400.
- New alerts include `trade_plan:{schema_version:1,analysis_id,kind:original_alert,alert_id,settings,result}`. Summaries omit this larger object. Backup restore reproduces the calculation from original evidence/settings. Legacy alerts remain supported. Planning failures preserve the alert with `planning_error`.
- Results identify `model_id:intraday-research-v1`, `research_only:true`, `calibration_status:unvalidated`, source/feed/time/expiry, levels, sizing, policy, reasons and warnings. See [TRADE_PLANNER.md](TRADE_PLANNER.md). There are no execution or fitting endpoints.

### Other research extensions

- GET `/api/health`: `{app:'nomisma',status:'ok',version:'2',data_directory}`. The launcher verifies both app identity and data directory before reusing a server.
- POST `/api/diagnostics`: `{}`. Tests the saved monitor configuration. POST `/api/discovery`: `{source,universe,symbols,min_price,max_price,min_day_volume,min_change_pct,limit}`. Both return HTTP 202 `{job:{id,kind,running,message,error,result}}`.
- GET `/api/research/jobs/<id>` returns the same job envelope. One research action runs at a time. At most 32 recent jobs are retained in memory. Restart clears this in-memory list; discovery settings, last-run metadata, and the last successful discovery result are persisted separately. A monitor start is refused while a diagnostic is running to avoid competing stream connections.
- Discovery result contains source/feed, request/completion/market timestamps, session date and market phase, universe label, requested/received/current-session/matched/returned/missing/stale/invalid counts, candidate rows, filters, and warnings. Rows carry symbol/name, latest price, day change, feed-day volume, timestamps, trade age, and freshness. Real discovery requires a current-session trade date and the exact previous-session close date; daily volume requires the current session date or an explicitly labeled current-session fallback. Regular-session trades older than five minutes are excluded. Outside regular hours any retained stale row remains labeled stale.
- New discovery defaults are price 0–1000, minimum total day volume 0, minimum day change −100%, and result limit 100 (allowed 1–500). Existing saved values are preserved. A zero minimum-volume filter permits an unavailable volume to remain visible; a positive threshold requires a qualifying measured volume. Historical metrics are displayed and ranked without introducing mandatory beta/ATR/average-volume filters.
- Candidate rows add `avg_volume_3m` (63 prior sessions), `avg_daily_volume` (20), `day_relative_volume` (fresh total day volume / 20-session average), `spread` (dollars), `spread_pct`, `spread_fresh`, `quote_at`, `beta`, `beta_observations`, `atr`, `atr_pct`, `history_as_of`, `history_expected_as_of`, `history_sessions`, and `metric_availability`. History dates exclude the active session. Missing values are null with availability explanations. Quote screening requires a valid quote no more than 30 seconds old; zero spread is valid. `day_volume_fresh`, `volume_basis`, and `volume_partial` identify volume quality. `volume_basis:'provider_daily_aggregate'` means current provider daily volume; `'completed_extended_minutes'` means a partial fallback of completed available minutes from 04:00 through 20:00 New York, never summed with a provider daily aggregate.
- Discovery `volume_at` identifies the actual latest completed-minute end for an extended-hours fallback, or the daily bar's timestamp for a provider aggregate. `volume_received_at` records response receipt separately. A fallback is fresh only when both receipt and its current-day completed-minute end are no more than 120 seconds old; a provider daily aggregate retains its 300-second receipt limit. Recheck freshness after historical enrichment. Stale fallback volume cannot pass a positive `min_day_volume`; with a zero minimum, retain the row and displayed partial total but mark `day_volume_fresh:false`, give that volume zero ranking points, and set `day_relative_volume:null`. The monitor's separate `volume_at` remains the regular-session technical minute end.
- After historical enrichment, real discovery refreshes missing, invalid, or older-than-30-second quotes only within the already selected ranking pool of at most 500 symbols. It calls Alpaca's fixed `/v2/stocks/quotes/latest` endpoint with the same feed and authentication, in batches of 50 with at most two concurrent requests. Fresh quotes and expired regular-session trades are skipped. Accept only positive finite bid/ask, ask at least bid, and an actual same-session provider timestamp aged 0–30 seconds at completion; recheck before final ranking. Requests never replace quote timestamps with receipt time or change trade/volume timestamps. Unusable or failed requests leave spread unavailable with a sanitized warning and zero spread points; cancellation propagates. Coverage includes `quote_refresh_requested`, `quote_refresh_loaded`, and `quote_refresh_unavailable`.
- Discovery applies existing filters, selects at most 500 matches by descending total day volume with ticker ties, enriches their daily history, then applies the shared liquidity/volatility ranking before the requested result limit. Missing historical metrics earn zero ranking points without dropping rows. The result also includes `ranking:{weights,pool_limit,benchmark}`, identifying SPY or the explicitly synthetic benchmark. Coverage adds `ranking_pool`, `ranking_pool_limit`, `ranking_omitted`, `extended_volume_requested`, `extended_volume_loaded`, `extended_volume_omitted`, `metrics_complete`, and `metrics_partial`. `expired_during_enrichment` counts prices that aged out; `expired_volume_during_enrichment` counts fallback volumes that aged out and failed a positive minimum-volume filter after loading history. The ranking describes that bounded pool, not all listings. Fallback requests and omitted matches remain explicit in warnings and coverage.
- Candidate and monitor rows expose `liquidity_volatility_score`, `rank`, `ranking_components:{metric:{value,weight,available,percentile,points}}`, `ranking_available_metrics`, `ranking_missing_metrics`, and `ranking_metric_coverage_pct`. Weights total 100: day volume 15, average 3M volume 10, average daily volume 10, day RVOL 20, inverse spread percentage 15, positive beta 10, ATR percentage 20. Percentiles are relative to available values in the current pool, with averaged tie ranks; a sole available value receives full component points. Missing values get zero without weight redistribution; nonpositive beta is measured but gets no beta points. Scores tie by ticker. This score is independent of the technical alert score. See [METHODOLOGY.md](METHODOLOGY.md#liquidityvolatility-ranking).
- GET `/api/discovery/settings` returns `{config,schedule,status,latest,job}`. `config` uses the same flat discovery fields accepted by POST `/api/discovery`. `schedule` is `{enabled:false,time:'09:15',timezone:'America/New_York'}` by default. POST `/api/discovery/settings` accepts partial `{config,schedule}`, validates the merged settings, and returns the same envelope. Saving does not start a search or change monitor configuration.
- Discovery `status` is `{enabled,running,last_run,last_success_date,next_due,retry_after,message}`. `last_run` is the latest job summary without its result, and `latest` is the complete last successful job or null. `job` is the active discovery job, otherwise the last-run job. Jobs add `started_at`, `completed_at`, and `scheduled_date` (null for manual searches) to `{id,kind,running,message,error,result}`. GET `/api/discovery/latest` returns `{job,status}`, choosing the running job while active and the last successful job otherwise. Failed searches leave successful results available.
- Candidate scheduling is independent of daily screening. It checks every 30 seconds and runs once per New York weekday after the saved time, including daylight-saving changes. Same-day startup catches up; missed historical days are not replayed. Success dates persist, failed scheduled searches retry after 15 minutes, and busy research work delays scheduling until another tick. An interrupted search is recorded as failed on restart and may retry when due. Weekday scheduling does not skip exchange holidays; the discovery result retains its market-closed explanation. The local service and computer must remain running. Scheduled discovery does not change monitor symbols, start a stream, or submit orders.
- GET `/api/monitor` and GET `/api/monitor/events` retain their full row snapshots by default. With `?compact=1`, both omit `chart` and `volume_history` from each row. Snapshots add `limits:{max_symbols:50}`. GET `/api/monitor/symbol/<ticker>` returns `{row}` with the full current row for report loading; invalid symbols return 400 and unavailable monitor rows return 404. Compact responses leave metrics, alerts, provenance, and CSV behavior intact. See [LIVE_CONTRACT.md](LIVE_CONTRACT.md) for the row schema.
- Monitor snapshot `alerts` are limited to the captured `config.source`, including while stopped. Filtering happens before the latest-100 limit, so saved synthetic alerts cannot displace Alpaca alerts or appear in the Alpaca **Setup alerts** panel. Switching the configured source changes this panel without deleting any saved alert.
- POST `/api/monitor/refresh` with `{}` returns HTTP 202 with a monitor snapshot and starts a background refresh. It requires an active connected live or demo monitor, and returns 409 if stopped, connecting, reconnecting, or already refreshing. `status.refresh` is `{state:'idle'|'loading'|'completed'|'error'|'cancelled',started_at,completed_at,error}`. Real refresh reloads quotes, prior daily history, current minute history, and optional float data while retaining newer stream updates and alert deduplication state. It bypasses the float cache; manual float overrides still take precedence. Demo refresh recomputes the current simulated minute. Stop/restart invalidates an in-flight refresh; errors retain existing stream data. Refresh does not rerun daily scans or candidate discovery.
- GET `/api/history?limit=20&offset=0`: `{history,total,limit,offset}`. GET `/api/monitor/alerts?limit=20&offset=0`: `{alerts,total,limit,offset}`. The alert journal retains all sources; this endpoint does not inherit the monitor panel's source filter. HTTP pagination accepts limits 1–100 and offsets 0–10000000.
- POST `/api/monitor/alerts/ack`: `{id}` or `{all:true}`, optionally with `source:'demo'|'alpaca'`, returns `{alerts}`. An explicit source scopes both acknowledgment and the response; an id belonging to another source is left unchanged. Omitting source retains the all-source API behavior. The main **Setup alerts → Mark all read** control always sends the configured source, so it does not acknowledge hidden alerts from another source.
- GET `/api/monitor/alerts/<id>` returns original alert evidence and observed outcomes, with legacy evidence explicitly unavailable. List and monitor SSE results omit the large original config/snapshot/session fields.
- GET `/api/workspace/backup` downloads a consistent SQLite snapshot. POST `/api/workspace/restore` accepts a raw `application/octet-stream` or `application/vnd.sqlite3` body, maximum 128 MB. The monitor, daily scan, and research jobs must be stopped/finished. The app validates the upload and preserves an automatic local safety backup before restoring validated table rows. Returns `{restored:true,backup_path}`. Restored monitor remains stopped; reload UI to reflect restored settings.

## UI (frontend agent owns static files)

Sophisticated high quality light warm-neutral financial research workspace. Dark slim sidebar, green accents, distinctive typography using available system fonts, generous whitespace, precise numeric alignment. Branding: Heuresis platform / Nomisma project. Responsive sidebar, dashboard KPI cards, market context chart, filter panel, ranked stock table with sparkline, selected-stock detail chart and score breakdown. Top nav Dashboard / Watchlist / Scan history / Methodology can be client views. All visible controls work. Source demo banner persistent when demo; data timestamps; no fabricated live metrics. Details of signal weighting read from API signals. Filter editor all filters; presets, save preset, daily schedule, CSV import/export, source selector and universe/custom tickers. Network credentials configured only via .env; connection UI explains concise instructions without asking users to enter secrets into frontend. Keyboard accessible dialogs, labels, focus, native buttons. Use inline SVG for charts/icons, no dependencies or external assets. Document and coordinate any API contract changes.
